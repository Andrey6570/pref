# CLAUDE.md: Преферанс (Сочинка), мобильная игра для iOS и Android

Работай в этом репозитории по правилам ниже. Подробности правил игры: `docs/SPEC.md`. Запуск и сборка: `README.md`.

## Что это
Мобильная игра в преферанс: офлайн, против ботов, потом возможно онлайн. Один движок правил на TypeScript и одно приложение на React Native (Expo) дают обе платформы. Автор планирует публиковать приложение в магазинах как физлицо.

## Структура
```
packages/engine/src
  cards.ts      карты, колода, сортировка
  config.ts     RulesConfig и конфиг SOCHI (все числа правил живут здесь)
  contracts.ts  заявки, старшинство (мизер = ранг 14.5, между 8БК и 9♠)
  types.ts      Game, Deal, Play, Action, PlayerView-типы
  engine.ts     newGame, apply (чистая, иммутабельная), validate, actingSeat, viewFor, legalBids/legalCards
  scoring.ts    scoreDeal (очки раздачи), settle (итог пули)
  bots/         random.ts (база для сравнений), heuristic.ts (бот v1)
  sim.ts        партии бот-против-бота: проверка инвариантов и замеры
packages/engine/test    vitest
apps/mobile             Expo SDK 58, App.tsx — весь интерфейс
docs/SPEC.md            подтверждённые правила и допущения
```

## Команды
```bash
npm install
npm test                       # тесты движка (должны быть зелёными перед любым коммитом)
npm run typecheck              # движок + приложение
BULLETS=300 npm run sim        # статистика ботов, доверительные интервалы
npm run start -w @pref/mobile  # Expo Go
```

## Архитектурные правила
1. **Движок не знает про интерфейс.** В `packages/engine` нет импортов React, Expo, Node API (кроме `sim.ts`, он только для запуска в Node). Должен работать в Hermes.
2. **Состояние игры — чистый JSON.** `apply(game, action)` возвращает новое состояние и ничего не мутирует снаружи. Не использовать `structuredClone` (нет в Hermes): есть `clone.ts`.
3. **Все числа правил только в `RulesConfig`.** Новая конвенция (Ленинградка, Ростов) = новый конфиг + тесты, а не `if` в движке.
4. **Сдача детерминирована** по `(seed, dealNo)`. Не вводить `Math.random` в движок и ботов.
5. **Бот получает только `PlayerView`** (`viewFor`). Подглядывание в `game.deal` из бота запрещено, кроме явно названного уровня «читер».
6. **Инварианты, которые нельзя ломать:** 32 карты без дублей на каждом шаге; итог пули в сумме равен нулю; каждая раздача с розыгрышем заканчивается ровно 10 взятками.

## Статус правил: что нельзя считать истиной
Часть правил подсчёта принята допущением (`docs/SPEC.md`, раздел 2, колонка «Уверенность»). Самые слабые:
- при одном вистующем рука пасующего открыта, ходит вистующий;
- равные заявки и приоритет первой руки;
- закрытие пули («помощь» не реализована, очки сверх цели обрезаются);
- распасы: порядок начала взяток, случай «никто не ответил в масть».

**Не меняй допущения «по ощущениям».** Меняй только по источнику или по записанной живой раздаче, и каждое изменение сопровождай тестом «известная раздача → известный итог». Если данных не хватает, скажи об этом прямо и не выдумывай правило.

## Известные проблемы бота v1
- Слишком осторожен: около 63% раздач заканчиваются распасами, мизер почти не заявляет.
- Не использует информацию из торговли и не рассуждает о скрытых картах.
- Параметры (`BotParams`) подобраны симуляцией против слабых соперников, а не против сильных.

## Как проверять изменения
- Правки движка: `npm test` и `BULLETS=150 npm run sim`. Убедиться, что нет незавершённых партий и сумма итогов равна нулю.
- Правки бота: сравнивать варианты через `sim.ts` с доверительным интервалом (95%). Разницу меньше интервала считать шумом.
- Правки интерфейса: `npm run typecheck` и запуск в Expo Go. Если запустить нельзя, так и написать, а не утверждать, что работает.
